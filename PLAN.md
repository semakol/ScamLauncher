# ScamLauncher — план

## 1. Что решили

| Тема | Решение |
|---|---|
| Платформы | Windows, macOS (arm64 + x64), Linux — сборка в GitHub Actions |
| Стек | Tauri v2 (Rust) + React + TypeScript + Vite |
| Сборки | Несколько, у каждой свой загрузчик: Fabric / Quilt / Forge / NeoForge |
| Версии MC | 1.16 – 1.21.x (Java 16/17/21) |
| Вход | Оффлайн по нику |
| Java | Лаунчер качает сам (официальные Java-runtime от Mojang) |
| Игра и загрузчики | С официальных серверов; в коде сразу закладываем зеркала |
| Хранение сборок | Публичная папка на Яндекс Диске; лаунчер читает её без токена |
| Формат сборки | Манифест + файлы, адресация по хэшу (content-addressed) |
| Публикация | Rust CLI `scam-pack` в том же репо, одна команда |
| Версия сборки | Номер билда растёт сам + метка `1.3.0` задаётся флагом |
| Бета | Бета-канал сборок; `promote` делает бету релизом; включается галочкой в настройках; папка игры одна |
| Обновление лаунчера | GitHub Releases + Tauri updater, **спрашиваем игрока** |
| Подпись | Без подписи ОС (SmartScreen/Gatekeeper покажут предупреждение); апдейты подписаны ключом Tauri |
| Папка игры | AppData/Application Support/.local/share, можно сменить в настройках |
| UI | Русский, тёмный, современный |
| Фичи | RAM + JVM-аргументы, новости и changelog, консоль логов и краш-репорты |

## 2. Архитектура

```
ScamLauncher/
├─ Cargo.toml                  # workspace
├─ crates/
│  ├─ scam-core/               # схема манифеста, pack.toml, glob/regex-матчер, хэши,
│  │                           # клиент Яндекс Диска, движок синхронизации файлов
│  ├─ scam-mc/                 # установка и запуск MC: Mojang meta, библиотеки, ассеты,
│  │                           # Java-runtime, Fabric/Quilt/Forge/NeoForge, аргументы запуска
│  └─ scam-pack/               # CLI для публикации (init / publish / promote / gc / status)
├─ app/
│  ├─ src-tauri/               # команды Tauri, события прогресса, апдейтер
│  └─ src/                     # React + TS
├─ scam.config.json            # ссылка на публичную папку Я.Диска, OAuth ClientID, репозиторий GitHub
└─ .github/workflows/
   ├─ ci.yml                   # cargo test + clippy + сборка UI на каждый push/PR
   └─ release.yml              # тег v* → сборка под все ОС → релиз + latest.json + бинарники scam-pack
```

Схема манифеста живёт в одном месте (`scam-core`), и её используют и лаунчер, и `scam-pack`, поэтому форматы не могут разойтись.

## 3. Яндекс Диск

### Структура публичной папки
```
ScamLauncher/                      ← опубликована по ссылке
├─ index.json                      # сборки, текущие билды каналов релиз/бета, зеркала
├─ news.json
├─ packs/<packId>/
│  └─ builds/<N>.json              # полный манифест билда
└─ objects/<ab>/<sha1>             # содержимое файлов, имя = хэш
```

Почему хранение по хэшу:
- при публикации заливаются **только новые** файлы, а одинаковые файлы в разных сборках и билдах хранятся один раз;
- бета и релиз используют одни и те же объекты, поэтому `promote` меняет только запись в `index.json`;
- откат админом (`scam-pack promote --build 40`) бесплатный: старые билды никуда не деваются;
- `scam-pack gc` удаляет объекты, на которые больше никто не ссылается.

### Доступ
- **Лаунчер:** `GET cloud-api.yandex.net/v1/disk/public/resources/download?public_key=<ссылка>&path=/objects/..` → `href` → скачивание. Без токена, 8 параллельных загрузок, повторы с backoff, докачка.
- **scam-pack:** OAuth-токен с правом `cloud_api:disk.write`, хранится в файле настроек пользователя (права 600) или в `SCAM_YANDEX_TOKEN`. `PUT /v1/disk/resources/upload` → `href` → PUT файла.

### Манифест билда (`builds/<N>.json`)
```json

  "pack": "techno", "name": "Техно", "build": 42, "version": "1.3.0",
  "created": "2026-09-18T12:00:00Z",
  "minecraft": "1.20.1",
  "loader": { "kind": "forge", "version": "47.4.0" },
  "memory": { "recommended": 6144 },
  "changelog": "## 1.3.0\n- Добавлен Create 0.5.1",
  "groups": [

```

## 4. Конфиг сборки у автора (`pack.toml`)

```toml
[pack]
id = "techno"
name = "Техно"
minecraft = "1.20.1"
loader = "forge"
loader_version = "47.2.0"
memory_recommended = 6144
source = "~/MC/techno"               # папка, из которой собирается сборка
exclude = ["saves/**", "logs/**", "crash-reports/**", "screenshots/**"]

# Правила проверяются по порядку, срабатывает первое подходящее.
# Шаблон — glob, с префиксом "re:" — регулярное выражение по относительному пути.

[[group]]
id = "mods"
mode = "sync"                        # всегда приводится к версии сборки
include = ["mods/*.jar"]
prune = ["mods/*.jar"]                # лишние jar в mods/ удаляются

[[group]]
id = "controls"
name = "Управление"
mode = "once"                        # ставится один раз
revision = 2                         # увеличил → у всех перезапишется один раз (с бэкапом)
include = ['re:^options(of|shaders)?\.txt$']

[[group]]
id = "shaders"
name = "Шейдеры"
mode = "once"
revision = 1
include = ["shaderpacks/**"]

[[group]]
id = "emotes"
name = "Эмоции"
mode = "once"
revision = 1
include = ["emotes/**"]

[[group]]
id = "configs"
name = "Конфиги"
mode = "once"
revision = 1
include = ["config/**", "defaultconfigs/**"]

[[group]]
id = "server-configs"
mode = "sync"                        # конфиги, которые обязаны совпадать с сервером
include = ['re:^config/(create|ftbchunks)-common\.toml$']
```

`pack.toml`, `mods-clients/`, `.scam/`, `.DS_Store` исключаются всегда. Если файл не попал ни в одну группу, `publish` выдаёт ошибку, чтобы ничего не опубликовалось случайно (`--allow-unmatched` отключает проверку).

## 5. Логика файлов в лаунчере (главная часть)

Папка экземпляра: `<root>/instances/<packId>/` (сама игра), `mods-clients/`, `.scam/state.json`, `.scam/backups/`.

`state.json` хранит: установленный билд и канал, ревизию каждой once-группы, список скопированных клиентских модов, кэш хэшей (path → size + mtime + sha1), чтобы не пересчитывать хэши при каждом запуске.

### Перед каждым запуском
1. **Проверка версии.** Скачиваем `index.json` (несколько КБ, в нём текущие билды всех сборок). Если билд новее, скачиваем манифест. Если интернета нет, а сборка уже установлена, запускаем то, что есть.
2. **sync-группы (моды).** Каждый файл сверяем по кэшу хэшей. Отсутствующие и изменённые файлы скачиваем заново. **Моды сборки всегда восстанавливаются.**
3. **mods-clients.** Читаем mod id из каждого `.jar` (`fabric.mod.json` / `quilt.mod.json` / `META-INF/mods.toml` / `neoforge.mods.toml`).
   - Если такой mod id уже есть в сборке, мод не копируется, и в UI показывается предупреждение «мод уже есть в сборке». **Приоритет у сборки.**
   - Остальные копируются в `mods/` и остаются там. Если игрок удалил мод из `mods-clients/`, копия удаляется и из `mods/`.
4. **Очистка (prune).** Всё в `mods/*.jar`, что не входит в сборку и не пришло из `mods-clients/`, **удаляется**. Это касается и модов, убранных из новой версии сборки, и модов, кинутых напрямую в `mods/`. Остальные файлы и подпапки в `mods/` не трогаются.
5. **once-группы.** Группа ставится, если:
   - её ещё нет в `state.json` (первая установка), **или**
   - корень группы пропал целиком (например, удалена папка `shaderpacks/` или файл `options.txt`), **или**
   - `revision` в манифесте больше сохранённой: старые файлы уходят в `.scam/backups/<дата>/`, после чего группа перезаписывается.

   Если игрок удалил из группы один файл, но корень на месте, файл не возвращается. Файлы, которые игрок изменил, не перезаписываются.
6. Всё, что не описано в манифесте (миры, скриншоты, `servers.dat`, свои ресурспаки и т.д.), лаунчер **никогда не трогает**.

### Кнопки
- **«Открыть папку клиентских модов»** открывает `mods-clients/` в проводнике или Finder.
- **«Восстановить файлы сборки…»** открывает окно с галочками once-групп (☐ Шейдеры ☐ Управление ☐ Конфиги …). Отмеченные группы сохраняются в бэкап и ставятся заново.
- **«Проверить и починить»** запускает полную проверку хэшей без кэша.
- **«Открыть папку игры»**.

### Бета
Галочка «Бета-версии сборок» в глобальных настройках. После неё в карточке сборки, у которой есть бета, появляется переключатель «Релиз / Бета». Папка игры общая: при переключении синхронизируются только sync-группы, а once-группы подчиняются тем же правилам ревизий.

## 6. Запуск Minecraft (`scam-mc`)

- **Mojang:** `piston-meta.mojang.com/mc/game/version_manifest_v2.json` → JSON версии → client.jar, библиотеки (с правилами под ОС и архитектуру), natives, индекс ассетов и объекты (`resources.download.minecraft.net`), конфиг log4j.
- **Java:** официальные runtime от Mojang (`java-runtime-alpha/gamma/delta`), компонент берётся из `javaVersion` в JSON версии. Работает на Windows x64, macOS arm64/x64 и Linux x64. В манифесте сборки можно переопределить.
- **Fabric / Quilt:** профиль с `meta.fabricmc.net` / `meta.quiltmc.org`, слияние по `inheritsFrom`.
- **Forge / NeoForge (самое сложное):** качаем installer.jar, читаем `install_profile.json` и `version.json`, скачиваем библиотеки и **сами запускаем processors** (так же, как Prism и HMCL), чтобы установщик Forge не пришлось запускать с GUI. Результат кэшируется в общей папке `versions/`.
- **Оффлайн-вход:** ник 3–16 символов `[A-Za-z0-9_]`, UUID = `nameUUIDFromBytes("OfflinePlayer:" + ник)` (как у ванильного сервера), `accessToken = 0`.
- **Зеркала:** весь сетевой доступ идёт через `Source` со списком базовых URL для каждого типа (`mojang-meta`, `libraries`, `assets`, `java`, `fabric`, `forge`, `neoforge`). Сейчас в списке только официальные адреса. Зеркала (BMCLAPI, свой Я.Диск) добавляются в `index.json`, без пересборки лаунчера.
- Общие `libraries/`, `assets/`, `versions/`, `runtime/` лежат в корне и используются всеми сборками.

## 7. Интерфейс

- **Главная:** слева список сборок (иконка, название, версия, значок «бета»). Справа фон сборки, changelog и новости, внизу поле ника и большая кнопка **«Играть»**. Во время работы вместо кнопки показывается прогресс: «Проверка файлов», «Загрузка 34/210 · 12 МБ/с», «Установка Forge».
- **Настройки сборки:** RAM (ползунок, по умолчанию `recommended` из манифеста, максимум зависит от памяти ПК), свои JVM-аргументы, канал релиз/бета, кнопки из п.5.
- **Глобальные настройки:** папка игры (с переносом), галочка бета-версий, JVM-аргументы по умолчанию, версия лаунчера и кнопка «Проверить обновления».
- **Консоль:** живой лог stdout/stderr игры, сохраняется в `.scam/logs/`. Если игра завершилась с ошибкой, открывается окно с последними строками лога и `crash-reports/`, есть кнопки «Скопировать отчёт» и «Открыть папку».
- **Обновление лаунчера:** при старте проверяется `latest.json` из GitHub Releases, при наличии новой версии показывается плашка «Доступна версия X — обновить?» со списком изменений.

## 8. `scam-pack` — публикация

```
scam-pack login                     # вход через OAuth Яндекса
scam-pack init                      # создать pack.toml
scam-pack status                    # что изменилось относительно опубликованного (dry-run)
scam-pack publish [--beta] [--version 1.3.0] [--changelog CHANGELOG.md]
scam-pack promote <pack> [--build N]   # бета → релиз или откат релиза на старый билд
scam-pack news add "Текст"          # новость в news.json
scam-pack gc                        # удалить неиспользуемые объекты
```

`publish` сканирует `source`, раскладывает файлы по группам, считает sha1 и достаёт mod id. Затем заливает на диск только отсутствующие объекты, записывает `builds/<N+1>.json` и последним обновляет канал в `index.json`. Манифест записывается последним, поэтому игроки никогда не увидят наполовину залитую сборку.

## 9. GitHub Actions

- **ci.yml** (push/PR): `cargo fmt --check`, `clippy`, `cargo test`, сборка UI.
- **release.yml** (тег `v*`), matrix: `windows-latest`, `macos-latest` (aarch64 + x86_64), `ubuntu-22.04`.
  - `tauri-apps/tauri-action` собирает `.msi`/`.exe`, `.dmg`/`.app.tar.gz`, `.AppImage`/`.deb` и `latest.json` для апдейтера.
  - Апдейты подписываются секретами `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
  - В тот же релиз прикладываются бинарники `scam-pack` под все ОС.
  - Версия берётся из тега и прописывается в `tauri.conf.json` и `Cargo.toml`.
- Апдейтер берёт `https://github.com/<you>/ScamLauncher/releases/latest/download/latest.json`. Pre-release туда не попадают, поэтому бету лаунчера при желании можно выкладывать как pre-release.

## 11. Что нужно от тебя

1. **GitHub:** создать публичный репозиторий `ScamLauncher` и прислать `owner/repo`.
2. **Ключ апдейтера:** сгенерирую его командой `tauri signer generate`, а ты добавишь два секрета в репозиторий. Ключ нельзя терять: без него существующие лаунчеры не примут обновления.
3. **Яндекс:** зарегистрировать OAuth-приложение на oauth.yandex.ru с правами `cloud_api:disk.read` и `cloud_api:disk.write` и прислать `client_id`. Ещё нужно создать папку `ScamLauncher` на Диске, открыть к ней доступ по ссылке и прислать ссылку.
4. **Тестовая сборка:** любая папка с модами (Fabric или Forge), на которой будем проверять.

## 12. Риски и допущения

- **Лимиты публичных ссылок Я.Диска.** При большом трафике Яндекс может временно ограничить скачивание. Это смягчают зеркала в `index.json` (можно добавить второй диск или S3). Кроме того, при хранении по хэшу обновления качают мало.
- **Forge / NeoForge processors** — самый трудоёмкий кусок, на него заложено больше времени.
- **Без подписи ОС** Windows покажет SmartScreen («Подробнее → Выполнить в любом случае»), а на macOS первый раз придётся открывать через ПКМ → «Открыть». Это нужно описать в README.
- **Linux:** только x64. На ARM-Linux у Mojang нет Java runtime.
- **Не входит в план** (добавляется позже): автоподключение к серверу, скины, Discord RPC, вход через Microsoft, английский язык.
